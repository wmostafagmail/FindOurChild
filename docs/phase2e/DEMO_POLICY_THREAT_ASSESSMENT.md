# DEMO-ONLY approval policy — threat analysis and residual risks

**Design assessment, not a completed independent security assessment.** No production gate is weakened, no new verifier/registry is implemented, no keys are trusted and no model/image body is acquired by this checkpoint. Review with the [policy matrix](DEMO_APPROVAL_POLICY_PROPOSAL.md) and [key procedure](DEMO_KEY_ENROLLMENT_PROCEDURE.md).

Protected assets include actual model/image identities, clean derivatives, private vectors/results, approver authority, case/tenant isolation, immutable evidence, source/build integrity and the distinction between a demonstration and validated missing-child identification. Threat actors include a malicious/mistaken operator, compromised approver/owner account, browser caller, cross-tenant staff user, stale/restored worker, tampered upstream or artifact store, and privileged host administrator. No ordinary signature or audit hash defeats a privileged host.
