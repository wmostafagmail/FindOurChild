# Demo governance automated negative-test design

**Design only: every scenario below is pending implementation and execution.** These64 scenario IDs are reserved planning identifiers, not collected pytest/native/browser selectors and not64 passing tests. Parameterized execution counts will be frozen only when tests exist. No fixture, key, signed record, registry or permit is generated by this document. Read the [owner approval scope](DEMO_POLICY_DESIGN_APPROVAL.md) and [engineering/provisioning checklist](DEMO_GOVERNANCE_IMPLEMENTATION_CHECKLIST.md).

## Harness, fixtures and evidence contracts

After separate engineering authorization, use owned isolated test environments and explicitly synthetic fixtures: public cryptographic algorithm vectors; test-only principals/registries; generated text/RGB buffers; bounded synthetic compressed streams; short-lived non-neural child processes; two fictional tenants with existing live grant/MFA/case-purpose fixtures; and an actual isolated PostgreSQL database. Any future ephemeral protocol-test keys/records are **test vectors, not appointed-human keys or real approvals**. They must never enter the real demo trust store or count as human evidence. Test injection belongs in a test-only harness, never an environment variable or production `trust-any` switch. No weight/image bodies or native model parsing are needed for this source-only design.

Pair denials with a valid synthetic control to establish that the relevant boundary, not an unrelated setup error, caused rejection. Positive controls may authorize only the synthetic harness operation; they cannot establish actual enrollment, fixture judgment, model loading or inference. Do not fabricate a real signature to make an end-to-end approval test pass. Native parser spies below consume generated benign bytes only, not dlib model files. Actual parser/load qualification remains a separately authorized A5 milestone.

Every future case must record requirement/selector, positive control, exact fault, commit/input digests, layer and command, expected minimized error/state, observed side-effect counters, exit/timeout, required audit outcome and sanitized artifact hash. For pre-acquisition rejection expect no network/key/quarantine creation. For pre-parse rejection expect no parser invocation. For worker rejection expect no candidate/result/outbox-success publication. Those are **expected invariants**, not current measurements. Required audit failure denies; it must not be logged as successful authorization. Keep raw diagnostic evidence private and publish only allowlisted metadata/canary-clean reports.

## Worker execution fencing and recovery — DG-W01–W16

Future layers: real owned Linux isolation/process tests and actual PostgreSQL/RLS/API/integration transactions. Use bounded non-neural helpers and explicitly synthetic results. A stub worker proves fencing only, not actual recognition. Fault tests must not affect unrelated host services or use real child media.

| ID | Negative fixture / injected fault | Required outcome and observable proof |
|---|---|---|
| DG-W01 | Attached Docker client dies while helper keeps running | Independent watchdog enforces deadline, kills/reaps job and denies publication. Client exit is not successful completion. |
| DG-W02 | Runtime/control-plane API hangs or disappears at deadline | Independent enforcement still terminates the owned job. If unavailable/unproven, isolation gate fails and dependent work stops. |
| DG-W03 | Watchdog/supervisor crashes or loses trusted authority state | No new work/publication; independently enforced expiry/termination demonstrated, not assumed from a worker-local timer. |
| DG-W04 | CPU-spinning versus sleeping helper exceeds CPU or wall deadline | Distinct hard limits enforced; quota throttling alone does not satisfy wall-time test. |
| DG-W05 | Bounded allocation helper hits memory ceiling/OOM | Whole job fenced/terminated, no partial success; actual peak/OOM/exit receipt retained. |
| DG-W06 | Descendant changes session/process group or exceeds PID/FD/output/temp limits | No escape from owned isolation/cgroup; complete termination/reaping, no host/socket/network access. |
| DG-W07 | PID/container identity reuse or wrong-job kill/cleanup request | Stable identity rejects mis-targeting; unrelated jobs/services remain untouched. |
| DG-W08 | Cancellation, old lease or requeue race returns a late synthetic result | Compare-and-swap fence rejects stale worker; one logical completion at most. |
| DG-W09 | Key/model/image/case/media/purpose revoked after enqueue/lease | Running job loses publication authority; no cached-grant bypass. |
| DG-W10 | Authority/selection/input revision changes during audit wait or transaction | Current-state recheck/transaction guard rejects stale snapshot; no partial outbox/candidate row. |
| DG-W11 | Foreign tenant/instance/gallery job or unauthorized raw-vector/model-path request | Actual runtime-role RLS/API denial; hidden rows do not affect visible ranks/counts. |
| DG-W12 | Crash between result/audit/outbox updates; required audit fails | Transaction rolls back or remains safely retryable/fenced; no visible unaudited success. |
| DG-W13 | Deadline expires between native completion and publication; clock rollback/uncertainty | Output discarded/held; no post-deadline candidate even if helper exited0. |
| DG-W14 | Restore old database/registry backup with revoked grants/tombstones and stale activation epoch | Starts inactive; independently current authority reconciled before reads/jobs, no rights resurrection. |
| DG-W15 | New UUID/time rerun attempts to replace a rejected unchanged evidence snapshot | Preserve semantic rejection/safeguarding invariants; no identity/custody decision or approval laundering. |
| DG-W16 | Error/log/trace exposes canary media/token/vector/identity; observer reports success despite missing required case | Sanitization/inventory verifier rejects artifact/gate; raw evidence retained privately, no skipped/mocked inference counted as pass. |
