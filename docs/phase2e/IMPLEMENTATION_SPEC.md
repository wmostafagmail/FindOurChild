# Phase 2E — isolated licensed recognition demonstration specification

Date: 2026-10-29. **Proposed for owner review; no Phase 2E implementation, model/image acquisition or inference is authorized by this document.** It refines E0–E2 of the approved [roadmap](../ROADMAP_PHASES_2D_3.md), without changing that packet or the Phase 0–2D implementation. Read the [artifact gates](ARTIFACT_ACQUISITION_GATES.md), [independent revalidation](LICENSING_AND_COMPATIBILITY.md), [test strategy and acceptance](TESTING_AND_ACCEPTANCE.md) and [pending traceability](TEST_MATRIX.md) together.

## Outcome and boundaries

Deliver an actual, reproducible CPU demonstration: permitted fictional photograph → clean authorized derivative → CNN face detection → five-point alignment → non-neural quality indicators → dlib descriptor → versioned PostgreSQL/pgvector storage → exact similarity retrieval → staff-only Phase 2D investigation. A scripted ordering, canned descriptor, unit double or prerecorded neural output cannot satisfy this outcome. Both missing-to-found and found-to-missing fictional searches are required.

Keep the existing `fixture_scenario` provider and its regression tests. Introduce an explicit, separately enabled `licensed_demo_model` provider only in a dedicated demonstration deployment after its gates pass. Label every page, job, comparison, export and report **synthetic demonstration; similarity is not identity confirmation**. An institution's operating approval is not needed for unrelated synthetic engineering; exact asset permission and technical safety are still prerequisites for acquiring/executing these particular assets.

No real missing-child records, arbitrary personal photographs, public/reporter biometric search, operational matching, automatic identity or negative-identity decision, claimant contact, custody disclosure or child release. No production model registry clearance, operational threshold, age progression, demographic classifier, model fine-tuning, GPU fallback or external inference service. Demo artifact/image authorizations use a separate namespace and cannot satisfy the existing real-child dataset/qualification approval protocol. All eight previously blocked qualification profiles stay blocked. Phase 2F's multi-image aggregation/calibrated open-set policies and Phase 3 release are separate authorizations.

The existing [bounded REA research](../REA_RESEARCH_REPORT.md) informs this design: keep guarded investigation separate from inference, preserve PostgreSQL outbox/lease processing, and avoid the examined distance-to-percentage presentation and external descriptive requests. Those observations support architecture choices only; they provide no model-rights grant, benchmark or approval to copy another application's code/assets. No new binary investigation or REA execution was needed for this specification.

## Deployment and trust boundaries

Use a separate full Compose/deployment project with a verified demo instance UUID, database identity, Keycloak realm/client, session namespace, private buckets, encryption keys, credentials, queues and reset fixtures. The qualification lab remains separate. No operational/research private DSN, case store, identity realm, key or bucket is mounted. Startup validates environment identity and synthetic data class against server-held configuration, not a browser field. Demo and operational credentials must fail when used against the other boundary.

The inference worker is a new isolated native process/container, not a native extension inside the existing Python 3.13.13 API. Initial target: Linux x86_64 CPU. Freeze exact Python patch, compiler, CMake, NumPy, codecs, BLAS/thread configuration, OS packages, base-image digests and compiled wheel hash during E0; do not invent a compatible lock now. Prefer testing the existing Python patch first, but unsupported builds require a reviewed separate worker lock, not downgrading the API. Pin CPU instruction requirements and CUDA/GUI-off build options explicitly; prove CUDA is unused. No `pip install dlib`/wrapper auto-download at application startup.

Qualify the source-only CPU build, ABI, locked dependency grants and offline execution controls before acquiring any pretrained weight or image. Obtain a reviewed code/license-only source projection with per-file identities from the pinned commit; dlib contains `examples/faces` photographs, so a full clone/archive or wrapper bundle is not an approved source-acquisition recipe. Exclude upstream example/test photographs, embedded dataset bundles and unreviewed artifacts, and record the projection separately from the upstream tree identity. This is A1b in the artifact gates; no runtime compatibility is claimed today. It tests toolchain/API contracts, not pretrained inference.

Separate build/acquisition from execution: reviewed build fetches only approved source/dependencies; offline runtime has nonroot UID, read-only root/artifact mounts, dropped capabilities, no host/socket mounts, bounded temporary filesystem, restricted internal services and no internet egress/DNS route. Fix worker process count, native thread count, memory/CPU/pixel/decompression limits, statement/lock timeouts, bounded queue and retry ceilings. These are measured E0 settings, not an excuse to silently skip difficult images. A model parser crash, OOM or timeout is a failed job with no published partial result.

Use distinct roles for acquisition approval, fixture import, job execution, vector retrieval, API projection and migrations. Add explicit expiring `demo_recognition` action grants alongside the preserved `synthetic_investigation` and paired case/media purposes; an NGO role, assignment or synthetic label alone confers no execution rights. Revoke/expire grants through the existing live authority boundary rather than caching decisions. API/browser/reporter roles cannot SELECT raw vectors, model paths or the asset inventory. Workers can process only leased, server-resolved authorized derivatives through narrow procedures; no arbitrary path, uploaded weights, dynamic plugin, URL or user-selected embedding space. Scoped internal authorization and the existing activation epoch bind every task to this deployment. Required audit persistence fails closed.

## Data and pipeline

Only the exact three weight files and prospective 48 images in the approved [proposal](../planning/demo/DEMO_ASSET_PROPOSAL.json) may enter E0 after explicit approval. Validate the original hash, scan/decoder result and clean-derivative hash/version before import. A synthetic checkbox, filename or content type cannot admit unknown bytes. Existing geometric Phase 2D fixtures remain valid for workflow tests, but are not facial inference successes. Do not import publisher demographic scores, captions, unrelated media or generators.

Each photograph retains independent source/derivative identifiers and hashes; capture-date lower/upper/precision, capture-age lower/upper/knowledge and age-reference intervals; provenance and permission/revocation version; scan event; decoding/transform version and uncertainty. Unknown is null/unknown, never zero or report date. The generated pair's relationship is fictional publisher linkage, not real identity evidence. Scenario ages and historical dates are authored fiction, not biological age labels or actual longitudinal observations. Do not infer them from face/EXIF or overwrite historical photograph metadata.

Pipeline states are explicit: `queued`, `processing`, `needs_face_selection`, `no_face`, `quality_hold`, `succeeded`, `failed`, `canceled`, `revoked`. A job is not a successful empty match because detection, audit or a dependency failed. Structured errors distinguish these states privately without leaking inaccessible cases. Lease token/deadline, authorization epoch and input revision fence every transition; after crash/retry only the current lease can publish. Replays with changed inputs fail.

1. Decode only approved clean RGB uint8 derivatives within fixed pixel/byte bounds, canonical orientation and declared color handling. Preserve lineage to original bytes; strip EXIF from displayed derivatives. Freeze any resize algorithm, dimensions and detector upsample setting in the space manifest. The upstream example's upsample=1 is not proof that full-size CNN processing meets the CPU budget.
2. Execute `cnn_face_detection_model_v1` with the exact detector. Zero faces is `no_face`. Multiple faces pause for an authorized staff selection of a particular bounded rectangle on the same derivative/version; never silently pick the largest, first or highest-confidence face. Staff selection is audited and changing it invalidates downstream results/reviews. Detection confidence is not identification probability.
3. Apply the exact five-point predictor to the selected CNN rectangle. Verify finite in-bounds landmarks and extract a 150×150 RGB face chip with dlib's transform and padding 0.25. Persist transform/selection hashes. Do not substitute the restricted 68-point predictor or a hand-rolled crop. Compare explicit-chip and direct-image binding outputs during qualification.
4. Compute documented non-neural indicators (pixel dimensions, clipping/exposure, blur statistic, face/chip size, landmark geometry and transform validity). Units, algorithms, limits and unknown states are versioned. These proxies do not reliably measure occlusion, age, identity, fairness or overall suitability; show unsupported attributes as unmeasured. Invalid geometry blocks embedding; other quality exclusions are predeclared and counted, not tuned on held-out success.
5. Execute the exact ResNet encoder on the aligned chip with `num_jitters=1`. The pinned binding uses the direct network path for <=1; it does not perform random averaging at one. Expect 128 finite native components, no implicit unit normalization. Record output dtype/cast policy; validate finite values, dimension and bounded norms before database insertion. Never replace failures with fixture vectors.
6. Store an immutable photo-version descriptor in the approved demo space. Every record binds organization/case/photo and clean derivative, face-selection version, input authority, detector/aligner/encoder hashes, preprocessing/quality/build versions, dimension/normalization and completion provenance. A changed photo, selection, transform, model, permission, space or policy requires reprocessing and a new result snapshot.

## Vector storage and exact retrieval

Add only forward migrations after the complete 0001–0036 ledger. Use separate demo model/space, job, photo-embedding and result-snapshot relations; final names/DDL require implementation review. All tenant-bearing relations force RLS, have NOLOGIN ownership, fixed-search-path narrowly granted functions, composite tenant/instance/resource foreign keys and no PUBLIC execution. Raw descriptors are available only to a narrowly scoped internal retriever with current purpose/case authority; never to public, reporter or general API direct-table roles. Preserve qualification-lab separation and existing research vectors.

Canonical embedding-space ID is SHA-256 of a versioned canonical serialization containing exact component/source/build/weight hashes, chip/color/resize/upsample/jitter/selection policy, dtype, dimension=128, normalization=`none`, metric=`euclidean_distance`, and transform version. Store the canonical manifest as well as its digest. Identical dimension or human-readable model name is insufficient compatibility. Old normalized-grid vectors and differently built dlib spaces cannot be compared. An upgrade creates another space; no in-place overwrite or cross-space fallback.

Begin with exact pgvector L2 (`<->`) under real RLS and explicit current instance/org/space/opposite registry/input authority/deletion checks before ranking or pagination. Bind each run to an immutable approved gallery manifest, split and enrollment revision; filter active enrolled members before distance/order. Processing an image never enrolls it. Absent-group originals/derivatives/descriptors and calibration groups cannot enter the sealed gallery, even if their bytes were approved for stage verification. The browser cannot widen the gallery or select another tenant/partition. No ANN/HNSW/IVFFlat or extra vector service in this baseline. Bound gallery/query size and work; fail explicitly above capacity. Compare SQL distances/order with a separately implemented double-precision L2 oracle, including vector storage float32 conversion, ties and a documented tolerance approved before held-out inference. Stable tie order uses an internal opaque ID; unauthorized rows cannot affect visible rank, counts or top-K through a global prefilter. Validate with sentinel high-scoring foreign-tenant rows and actual runtime roles; add bounded differential timing probes and report shared-resource residuals rather than claiming perfect timing noninterference.

Phase 2E uses one explicitly selected eligible gallery photograph per fictional case and one selected query photograph per run for the first demonstrable rank. Preserve all case photographs and their independent chronology, and bind every returned score to both individual photo versions. Do not average/max-pool multiple descriptors, select a favorable gallery photograph after seeing results, or label this baseline longitudinal matching. Multi-photo aggregation, calibrated open-set rejection and chronology-aware evaluation remain Phase 2F scope; the data model and contract leave room for them without implementing that phase now.

E2 must show measured native distance and rank, including incorrect ranks and failures, on the frozen intended gallery. This is an uncalibrated nearest-candidate demonstration, not a match assertion. Do not inherit dlib's published 0.6 example threshold, map distance to a confidence percentage, or interpret no output as proof of no identity match. If no independent demo threshold is approved, show `uncalibrated_demo` and make no accepted/rejected identity claim. No-face, insufficient authority, absent gallery and unavailable processing are distinct states. Open-set negative fixtures must never trigger automatic confirmation or operational actions.

## Phase 2D contract and review integration

The current [v1 provenance schema](../contracts/synthetic-candidate-source-v1.schema.json) is historical and its model arm is descriptive only. It currently requires `normalization=unit_l2`; current fixture import, photo provenance and publication code are closed to procedural fixtures. Consequently simply setting `licensed_demo_model` is not compatible. During implementation add a **v2 typed contract and additive provider dispatch**, generated OpenAPI/JSON Schema and runtime/database validators together. Preserve v1 fixtures, enum restrictions and tests; reject unknown providers, mixed spaces, source kinds and fields. Never relax the existing procedural hash gate globally.

The new source carries provider/schema version, `data_class=synthetic`, `identity_determination=not_performed`, exact model/component/build/space versions and weight digests, selected query/candidate photo references, `embedding_dimension=128`, `normalization=none`, `metric=euclidean_distance`, finite nonnegative raw distance, `score_semantics=native_l2_distance_lower_is_closer_not_identity_probability`, `aggregation_version=single_photo_pair_v1`, permission/acquisition references and `operational_activation=false`. No raw vector or storage URL is in the candidate DTO. Version internal artifact references separately from the minimized browser projection. Validate paired IDs, source hashes and same-space membership server-side; client-supplied candidate JSON/scores never create a lead.

Add proposed fixed staff operations under a new `/v1/staff/demo-recognition` namespace: status; create/read/cancel job; get authorized detections and submit selection. Final operation IDs, schemas, ceilings, rate limits and idempotency rules are implementation deliverables, not live endpoints here. Requests select server-known photo versions and preset policy only. Reject URL/file/model/gallery-tenant/threshold/raw-vector/provider overrides. Existing operational matching routes stay disabled. BFF forwards a fixed allowlist using the accepted server-held session, CSRF/origin controls and actual MFA; no browser bearer token or CORS widening.

Reuse Phase 2D candidate queue/comparison, tasks, immutable review events and independent safeguarding approval through a narrowly reviewed common provider boundary. Result publication atomically validates both cases, current media/workflow purpose and grants, model/image authority, lease, migration ledger, snapshot and epoch; writes audit/outbox and snapshot together. Recheck sensitive read/command authorization after durable audit waits. Media revocation removes references/projections and denies bytes; it also suppresses native scores, landmark/quality details and provenance derived from the now-unauthorized photograph, not merely the image response. Any still-authorized metadata-only lead must be explicitly unmeasured and require a fresh usable review snapshot. Case revocation denies the pair; model/image withdrawal invalidates results and approvals. Existing person-level independence, task expiry, stale review rejection and rejected-snapshot rules remain mandatory. Identical source-photo/selection/model/space/policy reruns retain the semantic rejection key; a new job ID or timestamp alone cannot launder a rejected lead into a fresh positive candidate. Keep raw descriptors, face chips and revocable per-photo score payloads out of append-only human journal events; reference separately protected result snapshots so deletion/withdrawal can remove derived evidence while retaining minimized actor/reason/time/hash history. Journal immutability is enforced against runtime roles; database/host administrators remain a governance threat, not defeated by an ordinary hash chain. Assignments confer no case rights. Completion means investigative review complete, never identity established, custody disclosed or child released.

Arabic/English screens must distinguish actual measured similarity from scripted fixture order, show per-photo uncertainties, uncalibrated status, pipeline failures and prohibited identity conclusions. Use local messages, logical CSS/RTL, keyboard/focus/live status, bounded pagination and responsive comparison. Never place raw vectors, claimant contacts, custody location, original EXIF, model paths or private dataset inventory in the page/URL/notification. No demo-photo screenshot is published without the artifact policy's review.

## Revocation, recovery and performance

Deletion/withdrawal disables jobs/retrieval and tombstones descriptors, selections, chips and derived snapshots before cleanup. Job cancellation is fenced; a delayed worker cannot republish removed data. Keep minimized immutable audit references without retaining deleted photographs/vectors. Restore into quarantine with a new instance/activation epoch; reconcile current grants, model/image withdrawals and tombstones before reissuing any execution or view rights. Test actual database and encrypted media restore, vector cleanup and old-backup replay. Synthetic recovery evidence is not production erasure certification.

Carry the unchanged [Phase 2D performance corrective plan](../phase2d/PERFORMANCE_FINDINGS_AND_PLAN.md) and [manual Phase 3 gates](../phase3/MANUAL_ACCEPTANCE_GATES.md). Two queue and two direct-database planning misses in the first four comparable runs remain open; the two later passing envelopes do not establish a fix. Additional main measurements are observations, not closure. Do not pool percentiles, change the four-core workload, remove durable audit/reauthorization, lower coverage or relabel a proposed eight-core reference as the old environment.

For inference, E0 must declare the initial proposed eight-core/16 GiB Linux x86_64 CPU reference, thread limits and full workload. Measure cold load, warmed stages, queue delay, service time, end-to-end time, p50/p95/p99, peak RSS, throughput, failure/timeout counts and colocated API interference. The roadmap's per-photo p95 <=5 seconds and <=30-second job ceiling are **unverified proposed targets**, not results; define timing start/stop, photo/pixel count and job semantics before execution. A missed target requires a reported blocker/corrective proposal or explicit owner disposition, never silent relaxation or a hidden HOG/GPU switch. Performance instrumentation/corrections require reviewed implementation and the full regression suite.
