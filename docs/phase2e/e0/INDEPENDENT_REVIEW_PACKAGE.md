## Native parsing and integrity threat boundary

The current guard denies before session construction, file opening, model parsing and forward calls. Capability is compiled false; all three fixed component identities are `nullopt`; even changing the constant encounters unconditional unprovisioned-authority denial. The Python flag is informational and cannot authorize execution. No runtime path/URL/plugin/manifest setter is exported.

Future native dlib deserialization is an untrusted C++ parsing boundary despite a licensed, authenticated source/model. Length fields, tensor dimensions, graph/feature counts and serialized state can cause allocation amplification, integer/geometry errors, excessive recursion/CPU, exceptions, hangs, crashes or memory corruption **before** postconditions. A 64 MiB file ceiling and SHA-256 identity do not bound parser allocations or prove safety. Decompression/image decoding add separate attack surfaces and are not approved here. The three parsers need later approved fault/corruption/fuzz/resource testing; none has executed under this checkpoint.

`VerifiedStream` checks every parent via `openat`/`O_NOFOLLOW`, root ownership, no group/other-writable directories, and a root-owned nonwritable regular file with one link and exact expected size/hash. It holds one FD, reads with bounded buffering, checks metadata/digest before and after parsing and rejects trailing bytes. Holding the FD prevents pathname replacement from selecting another inode. It **does not freeze that inode**: privileged host/root writers or another writable mount can modify bytes after prehash or during parsing. Posthash/stamp rejection can detect drift only after native code has consumed bytes; it cannot undo exploitation. Read-only container mounts alone do not establish host immutability; timestamps are not an authority boundary. A trusted immutable store or reviewed sealed snapshot/provisioning design, including host threat assumptions, is required before any parse permit. It is not implemented or certified by this package.

The future trusted registry must bind independently approved component identity, exact compressed/decompressed size and hashes, rights/provenance, source/build/preprocessing version, deployment scope, expiry/revocation and separate reviewer/operator authority. Actual trust roots, signed real manifests, registry provisioning and revocation enforcement are **not provisioned**. Synthetic test keys are not authority. No browser-uploaded or caller-selected registry entry is acceptable. A new exact-build/manifest review is required; this handoff specifies questions, not an approved registry design or real artifact identities.

## Process bounds and parser failure behavior

Current source-only runner: native Linux x86_64, UID 10001, read-only root, no mounts/devices/capabilities/network, no-new-privileges; cgroup **2 CPU quota / 1 GiB memory and same memory+swap ceiling / 64 PIDs**; **64 MiB noexec/nosuid/nodev tmpfs**. Probe limits: **CPU 10 seconds**, **core 0**, **regular output 1 MiB**, **64 FDs**, one native thread. The quota throttles CPU; it is not a wall-time guarantee. The 60-second external subprocess timeout kills the attached Docker client, with container termination attempted in `finally` via `docker rm --force`; Docker/control-plane failure can delay cleanup. This is not proof of an autonomous, hard 60-second worker deadline. Review supervisor failure behavior before execution authority. FDs/output limits do not bound RSS; cgroup/OOM termination is a last-resort limit, not graceful completion or tested parser safety.

Future ordinary C++ exceptions inside the guarded operation are minimized to `component_execution_failed` and fault the provider; later operations deny. Current review denial is outside that catch. Predictor/output schema and EOF checks compile but remain unexecuted. SIGSEGV, SIGKILL, OOM and hangs cannot be promised as catchable exceptions. Future external supervision must kill/reap the whole job, fence leases/publication, discard partial outputs, prevent unsafe retry and retain minimized failure evidence. That model-worker/application integration is pending, not established by source probe success. Proposed future hardware and inference latency budgets remain unqualified; no source-only limit approves them.
