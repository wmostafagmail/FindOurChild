# Initial source projection — policy failure and correction

The first standard-binding build acquired and compiled the pinned upstream file `dlib/image_processing/frontal_face_detector.h` (219,037 source bytes). It contains a base64-encoded pretrained HOG detector, as its source comment explicitly identifies. The header was included by the standard Python object-detection binding. Filtering by file extension did not establish a data-free source projection. This was missed during initial projection preparation.

No HOG detector was invoked: the exercised code imported the module, checked declared APIs and transformed generated RGB arrays using supplied fictional landmarks. No CNN/ResNet/five-point model file, 68-point weight, dataset image, real missing-child record or operational biometric processing was acquired/executed. **An incidental additional pretrained payload nevertheless entered the source/build; the broader claim that the initial build contained no pretrained material is invalid.** This is not excused by its presence inside a licensed source header.

The original projection, its source receipt and all CI attempts are preserved privately and in their original Git/Actions history. The original `source-only-qualification-586.json` is integrity/ABI/transform evidence only. Its historical `pretrained_assets_present=false` claim was based on file extensions and cannot satisfy A1b. Successful Actions status does not override this policy finding. Do not use the original standard-binding image or receipt for acquisition, loading or inference approval.

Named model weights and the 48 images remain unacquired. `config/phase2e/qualification-policy.json` now blocks the intake entry point before network or filesystem acquisition, independently of any source-only test status. No dummy technical-review record can clear that policy. Existing eight qualification profiles and every operational restriction remain blocked.

The correction is an isolated minimal binding/projection for review: exclude the embedded detector and all broad upstream Python bindings; expose generated-array chip transforms and compile-time declarations of the selected CNN/ResNet/five-point types only, with no HOG, file/image loader, pickle, arbitrary model path or execution API. Preserve the pinned dlib core source without patching it. Source-only prototype checks cannot constitute actual model execution or complete A1b/E0. The revised worker design/manifest must be reviewed before acquisition, as required by [A1b](../ARTIFACT_ACQUISITION_GATES.md): “If incompatible, revise only the isolated worker design for review”. A3/A4/A6/A7 independent actual-byte/fixture/execution approvals remain separate later gates.
