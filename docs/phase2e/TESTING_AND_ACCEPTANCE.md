# Phase 2E testing strategy and acceptance criteria

Status: **design only; every new Phase 2E test, native build, model run and performance measurement is pending**. Current functional regression evidence does not test this unimplemented provider. Preserve all prior required selectors and [Phase 2D testing](../phase2d/TEST_TRACEABILITY.md), source manifests and independent artifact checks. Planned features/cases are in [TEST_MATRIX.md](TEST_MATRIX.md); implementation must add actual collected selectors, explicit inventories and evidence links before claiming coverage.

The current regression baseline is 747 Python tests, 360 official browser cases (120 per engine, 15 journeys ×24 targets), 36 migrations and real PostgreSQL/RLS/API/security/recovery. These counts must be recalculated from actual collection after additions, never used as a substitute for required-test membership. Tests not run, canceled, skipped, retried away or mocked remain pending/failed. Browser testing does not replace database, security/penetration, native parser or biometric evaluation.

## Reproducibility and demonstration results

Freeze the original 24 fictional groups before inference: eight calibration groups (six enrolled, two absent) and sixteen sealed demo groups (twelve enrolled, four absent). Gallery uses the declared enrolled base images and probes their linked headshots; absent groups stay absent. Do not mix calibration and sealed-test galleries implicitly. All crops/duplicates/augmentations stay with their group. Independent visual correspondence review must not use model scores. Describe any resulting exclusion as a limitation and keep the complete intention-to-process failure ledger; do not replace unsuccessful fixed pairs silently.

Report detection/alignment/embedding/quality/timeout failures and denominators, same-build repeated-output tolerance, exact ranks, intended-correspondence rank distribution and workload (candidates inspected) for the actual fixed galleries. Recall@K on the twelve-subject sealed enrolled gallery must disclose its small size; K=50 exceeding the gallery is not evidence of large-gallery retrieval quality. In 2E, absent probes return uncalibrated nearest candidates, never automatic confirmation. FPIR/FNIR at a threshold are **not measured** until Phase 2F separately defines and freezes a calibration-only threshold and open-set protocol. Do not claim a valid rare-error bound or real child-identification accuracy from 48 generated images or correlated views. Report zero denominators as undefined, not 100% success.

Functional software tests, native demonstration results, independent authorized longitudinal-child evaluation and operational approval are four separate report sections. Keep the legacy `synthetic_model_smoke.real_models_benchmarked=0` claim scoped to that existing synthetic lane. Add separate `licensed_demo_inference` receipts with actual executed model/image counts, stage outcomes and artifact/space identities; do not reuse the smoke receipt as evidence of native execution. `real_models_qualified=0` still refers to unapproved real-child qualification and must not be misread as a claim that no demonstration model executed. The latter two remain unapproved/unmeasured. No demonstration age/date metadata represents real aging; no population fairness, child age-gap robustness or missing-child safety claim follows from a passed software suite or dlib's published unrelated benchmark.

## CI and evidence gates

Every implementation PR runs complete existing required validation plus all new affected suites. Keep the current strict/app-bound `phase1a-required` gate and its coverage floor; any added actual-inference job must become an explicit required status check before acceptance rather than an optional green aggregate. Require all configured engine/locale/viewport targets, all required native tests and all security negatives. Missing permitted assets, missing browser binaries, job timeout or unavailable private runner/credentials blocks the dependent gate; no green skip or `continue-on-error`. Use reviewed controlled runners/private stores for assets; untrusted fork PRs cannot access them or claim complete validation.

Retain commit/tree and execution-source manifest, commands, selected tests and zero-skip counts, all migrations/checksums, real RLS/restore receipts, dependency/security findings, native input/artifact/space IDs, sanitized numerical results and hardware timing data. Keep originals/weights/aligned chips/vectors/landmarks/raw DOM/logs/tokens/credentials privately with restricted access and retention limits. Public artifacts contain allowlisted counts/states/digests and reviewed input-free captures/minimized traces, not facial media or vectors. Scan output and verify canaries/checksums independently. Preserve original failures and label any unit/integration mock explicitly.
