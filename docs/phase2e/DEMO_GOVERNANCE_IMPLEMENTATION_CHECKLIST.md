## Contract details to freeze before coding

**V2 signed records.** Separate kinds for policy acceptance, enrollment/revocation, owner scope, technical preflight, A3 intake, A4a processing plan, A4b output audit, A5 load plan/result, A6 fixture record, A7 execution and A8 acceptance. A kind cannot imply another action. Bootstrap identity verification remains out of band and cannot be authorized by a candidate key's own signature.

Proposed bounded canonicalization: ASCII field names/authority identifiers; UTF-8 canonical JSON with sorted keys, compact separators and explicitly specified escaping; closed fields, no duplicate keys/floats/nonfinite values, safe bounded integers and exact UTC time strings; unique bounded predecessor-digest arrays. Sign domain bytes, record kind and canonical payload with unambiguous delimiters under `FOC-PHASE2E-DEMO-APPROVAL-V2`. Do not call this format RFC8785/JCS unless a conforming implementation is actually selected/verified. Proposed permit cap16KiB, nesting depth4 and <=16 predecessor references need review as engineering limits; they are not approved model/decompression limits. Oversize/unknown/noncanonical inputs deny before expensive verification. Freeze the exact cross-language byte vectors and limit values before implementation acceptance.

**Registry.** Store canonical Ed25519 SPKI DER and its SHA-256 fingerprint, actual person/principal linkage, owner designation, roles/gates, project/instance, validity, owner authorization, possession evidence and current revocation/registry epoch. The fingerprint format is DER-specific; raw-key hashes must not be substituted. Reject algorithm/encoding/trailing-data ambiguity. O authenticates each real enrollment; the tool must not infer authority from a successful signature, Git account or synthetic fixture. Registry files/configuration remain private, least privilege and not browser-selected.

**Immutable bytes.** Recommended Linux design: copy only a fixed approved component into a bounded anonymous snapshot, apply kernel write/grow/shrink/seal locks, and verify the snapshot's exact size/SHA-256 against the approved registry **after sealing and before parsing**. Feed native parsing only that sealed descriptor/stream, never a reopened mutable pathname. Preserve original path/ownership/type/link/size checks and reject inconsistent copy observations. Require source-only tests for symlink/path replacement, concurrent mutation, unsupported seals, hash drift and resource exhaustion. If sealing/immutability cannot be established, fail closed; no hash-only fallback. Privileged host/kernel compromise remains a residual threat. This is a proposed replacement for the known TOCTOU limitation, not an implemented fix or A4/A5 approval.

**Deadline and publication.** The trusted supervisor must survive loss of the attached Docker client, prevent worker PID/cgroup escape, use stable job/process identities, kill/reap the complete job on deadline and retain bounded failure evidence. A worker-side timer or CPU quota alone is insufficient. If the required Linux enforcement features are missing or termination cannot be demonstrated, the isolation gate fails. After any audit wait and again at the publication transaction, recheck current key/artifact/case/media/purpose grants, expiry, registry/activation epochs, input/selection revision and the current lease fence. Transaction failure, revocation, deadline loss, cancellation or restore rollback yields no candidate/outbox success. No UUID-only retry can launder a rejected unchanged investigation snapshot.
