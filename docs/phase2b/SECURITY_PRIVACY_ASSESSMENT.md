# Security and privacy assessment

Scope: synthetic qualification preparation, not production certification or an independent penetration test. Existing case/authentication/media safeguards and full regressions are preserved. Operational recognition, public facial search, automatic identity confirmation and custody disclosure stay disabled. All real model downloads and loading remain blocked independently of configuration flags. No real child image, pretrained weight or external testing-model call is part of this phase.

The new lab is a distinct PostgreSQL container/cluster and internal-only Docker network with no published ports, operational roles, case schemas, application DSNs, case object storage, IdP/session keys or notification services. Tester mounts are read-only source/evidence plus only its private output and newly generated lab secrets. It does not mount the workspace root, operational .runtime or earlier raw test reports. Native metadata dump/restore checks restored RLS and revoked-grant denial. Four lab tables force RLS, use synthetic-only/lineage constraints, and grant the runtime read-only access. Protocol/dataset/principal/organization/purpose/expiry/revocation checks govern visibility; runtime cannot grant rights or undo revocation. SQL context is set by a trusted internal caller, not an authorization mechanism for untrusted users with raw SQL access.

Phase 2A research relations in the application test database are retained only for the approved synthetic integration regressions. They are not a real-child research store. Future private photographs, model artifacts and linkage ledgers require separately approved accounts, networks, encrypted storage and key custody. A host administrator or Docker controller can bypass local container separation; this fixture lab is not approved for real data or multi-tenant hostile-host isolation.

Threats and controls: fraudulent authority/self-approval (independent bound synthetic approvals; future human/legal authority gate); manifest substitution and unknown artifacts (closed schema, source and declared artifact hash binding; future signed actual-byte verification); restricted downloads/SSRF (no downloader or network-capable model loader); dataset relabeling/duplicate/split leakage (known fixture identity/hash/event mapping and subject/family partition checks); cross-organization access (real RLS/FKs and negative tests); revoked/expired permissions (fresh statement checks and restored revocation test); raw-data export (closed aggregate evidence and no real-data entrypoint); model supply-chain execution (no real runtime now; quarantined future parser plan); public/custody exposure (unchanged disabled routes and live authenticated browser/API regression).

Limits: metadata labels alone cannot establish lawfulness; the executable image gate therefore accepts only known procedural hashes. Synthetic grant fixtures are not signed real-world credentials. No private child deletion, legal entitlement, real biometric accuracy/fairness, model/parser safety or hardware capacity is certified. READ COMMITTED revocation affects subsequent statements; a revoked operator may already possess bytes or an in-flight snapshot. A future approved system needs bounded jobs, cancellation and a second fresh authorization check before every export, plus verified deletion/tombstone and backup policy. These remain approval blockers.

Private diagnostics and dumps stay ignored/local or inside disposable CI. Public/reviewable artifacts export required test IDs/status, approved counts, coverage, input-free screenshots and minimized traces only. No child pixels, vectors, identities, source manifests, precise dates, contacts, case links, credentials, raw DOM or custody locations may appear. Test results cannot replace independent legal, safeguarding, privacy or penetration review.
