# Hardware and safe inference evaluation plan

No model runtime, GPU inference dependency or real weight has been installed. Compatibility and minimum hardware requirements are unverified. The current pinned Python 3.13.13/Node 24.18.0 application environment is not evidence that old AdaFace PyTorch examples or any ONNX provider works in it. Do not install obsolete upstream conda/runtime pins into the application.

After separate rights and evaluation approvals, build a dedicated offline image for each artifact/provider. Pin the OS/container digest, runtime/wheel hashes, driver/CUDA/cuDNN versions, CPU architecture/ISA, GPU and numerical precision; scan dependencies and create an SBOM. Every detector, aligner and model artifact must have an independent manifest and compatible grant. No wrapper defaults, model packs, arbitrary paths/URLs, cache auto-downloads or fallback providers. An unavailable requested provider fails the experiment rather than silently using CPU or another graph.

Before any parsing, verify immutable publisher reference, approved binary size/hash, signatures/trust roots where supplied, rights, revocation and full external-data closure. Quarantine the artifact without executing it. Inspect only in a patched, no-egress, nonroot sandbox with read-only input, bounded memory/process/time and disabled custom ops/plugins. ONNX is not intrinsically safe: reject unreviewed external tensor paths, custom operators, dynamic/unbounded shapes and parser/runtime vulnerabilities. Pin an operator allowlist and input/output shape/dtype limits. Model metadata inspection itself needs the same isolation.

Do not execute AdaFace's example torch.load on an untrusted checkpoint. Pickle/checkpoint deserialization is blocked; a future trusted conversion needs separate clearance, reviewed weights-only/safe serialization, pinned supported tooling and output parity. Conversion is not a licensing workaround. Compare exact channel order, numeric range, normalization location, landmark geometry, resize/crop rounding, output dimensions/L2 normalization and no-face/multi-face behavior against the reviewed source on separately approved inputs. No all-512-dimensional embedding spaces are presumed compatible.

Planning experiment budgets, not measured requirements: CPU x86_64 and arm64 at 4/8 cores and 8/16 GiB RAM; optional NVIDIA 16 GiB GPU only when a legal artifact/provider is qualified. Record model/detector declared file sizes from the register separately from RAM/VRAM needs; graph size is not inference memory. CPU-only support is a hypothesis until tested. Test batch 1 first, then 8/16 if permitted, thread counts 1/2/4, cold startup and at least 50 warmups/500 timed requests with proposed budgets independently reviewed. Measure p50/p95/p99 end-to-end and stage latency, throughput, RSS/peak VRAM, queue wait, rejected inputs, timeouts and power/resource contention. Record sample counts and confidence intervals; do not repeat until a preferred result appears.

Compare FP32 CPU/provider outputs first; FP16/INT8/CoreML/OpenVINO/accelerated exports each need a distinct artifact/space and pre-registered numerical and ranking parity limits. Check calibration and full demographic/age-gap endpoints, not only cosine closeness. SFace/YuNet native OpenCV and DeepFace's SFace preprocessing are distinct paths; require explicit geometry and value-range parity. Runtime/provider and performance pins remain pending, not guessed compatible versions.

Test gallery sizes and photo-count distributions only within authorized sample limits; synthetic 100/1,000/10,000-case engineering experiments may estimate infrastructure, not child accuracy. PostgreSQL exact retrieval is the baseline. ANN/HNSW, distributed galleries and operational capacity are not provisioned or qualified by this work. Test crash/restart, OOM, corrupted artifacts, provider failure, revocation during queues and cancellation before export. A failed sensitive step returns no candidate result and never invokes a public/external fallback.
