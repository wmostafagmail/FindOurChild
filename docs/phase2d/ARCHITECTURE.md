# Phase 2D synthetic investigation implementation

This document describes implementation under validation. Phase acceptance remains pending hosted evidence and owner review. The original approved specification and roadmap are retained unchanged.

The staff-only Next.js workspace at `/en/investigation` and `/ar/investigation` uses the fixed BFF and accepted live Keycloak MFA/session/CSRF boundary. Fourteen closed synthetic workflow operations are additive to the 49 preserved contracts. Generic operational matching, lead review, custody disclosure and handover remain disabled. `synthetic-candidate-source-v1.schema.json` specifies current fixture provenance and a descriptive future model variant; current routes accept only fixture provenance and never load a model.

Forward migrations 0025–0029 add eight explicit synthetic relations (five app, three platform). Every relation forces RLS and is owned by NOLOGIN `foc_owner`. API has scoped SELECT and bounded definer functions; worker has only lease/publication functions and existing media/outbox procedures. No API/worker access is granted to research vectors, qualification data, biometric manifests, custody, approval or release tables. Applied 0001–0024 bytes are preserved. Definers use fixed search paths and revoked PUBLIC execution. Pair/run/query/scenario and event/task references use composite tenant keys. Events cannot be updated/deleted by either runtime or policy writer; ordinary-role immutability and hash chains do not defeat administrators.

Workflow grants require the separate fixed `synthetic_investigation` purpose, active organization/principal/membership and explicit actions/expiry. Existing case grants still require fixed `case_management`. Both query and candidate case permissions apply before row projection, pagination, actions and media. Assignments create tasks only; no case grants are issued or renewed. Canonical person identity/conflict clearance comes from the controlled fixture provisioner, never a JWT role or browser assertion. Independent completion additionally requires a distinct person, assigned live task, exact first review/snapshot and safeguarding membership. A second account belonging to the same person fails.

A private operator provisions fictional cases, closed geometric fixtures and immutable manifests. Actual quarantine, encryption, ClamAV and private immutable derivative processing must succeed before source hashes/versions are sealed. Unknown original hashes cannot be admitted merely by labeling data synthetic. The initial ranked scenario includes three candidates, two metadata-only candidates, multiple independently dated source photographs, missing dates/ages and attributed contradictory statements. There are no real people, facial embeddings, neural similarity measurements or model binaries.

The actual worker leases bounded scenarios with fencing tokens/deadlines/retry exhaustion, validates fixture/case/evidence state and current requester rights before publication, then atomically publishes opposite-registry candidates. No arbitrary model, URL, candidate JSON or embedding can enter a run. Candidate/chronology projections are closed; raw score is null and explicitly scripted ordinal. Missing/estimated dates and ages stay independent per photograph; no face/EXIF/report-time inference occurs.

All decisions, structured notes, assignments and independent review events retain actor, canonical person, server time, snapshot, reason codes and previous/event hashes. Case locks use canonical ID order, followed by aggregate/idempotency locks. Revision, snapshot and command digest checks prevent stale writes, body-changing replay and duplicate events. Audit/outbox/current projection/history commit together. Sensitive reads persist audit before returning. Denial audit stores the organization and fixed action only, not guessed child IDs or request content. Audit failure denies/rolls back rather than implying success.

Prior paired decisions remain visible with timestamps/reasons and same-snapshot labeling. An identical rejected snapshot is held on a subsequent run and cannot be escalated unchanged. A new authorized evidence/policy snapshot requires fresh human decisions; no historic event is overwritten. A hold remains possible without inventing evidence. No outcome changes case identity verification, contacts claimants, discloses custody or releases a child.

Cursors are authenticated/encrypted, actor/org/resource/filter-bound, short-lived and invalidated by projection changes. Authorization filters precede ordering; visible ranks are contiguous. Queue/history pages are bounded without deleting/truncating history. Private pages reauthorize on restore/focus, clear evidence on expiry/revocation/dependency denial/logout, and guard stale asynchronous results with a session-generation token. No offline cache, local token store, signed media URL or original-image fallback is added. Bytes already legitimately viewed cannot be recalled instantaneously.

Synthetic task outbox recipients are narrowed to the authorized actor/assigned target and rechecked for current paired/workflow rights at delivery. The private neutral sink has task references and a workspace link only. No external notification/LLM service runs.

The independent activation epoch is private server configuration outside database backups. A restored copy has neither an accepted database identity nor reissued epoch; restore remains quarantined pending current permission/tombstone reconciliation. This is a synthetic recovery boundary, not production erasure certification. Production or restored operating credentials are never introduced.

Arabic/English controls, explanations, dates, tasks, errors and warnings are local messages, with logical CSS, stable source/candidate order, bidi-isolated references, keyboard controls, focus/status announcements and responsive stacking. Automated axe/three-engine checks are mandatory. Manual native-language/screen-reader assessment is reported separately, never inferred from automation.
