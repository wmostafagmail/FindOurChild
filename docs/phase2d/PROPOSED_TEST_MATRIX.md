## Route, SQL and adversarial expansion

Before coding, freeze an actor×operation inventory for all 14 proposed operations: anonymous, reporter, other organization, query-only grant, candidate-only grant, admin without case grant, expired/revoked purpose/action/media grant, active authorized actor and disabled/suspended actor. Every sensitive operation needs negative HTTP and actual-PostgreSQL tests. Action-specific cases include invalid CSRF/Origin, forged JWT AMR/role, IDOR/SSRF/path traversal, oversized/malformed DTO, SQL context/pool contamination, guessed cursor, copied image path, evidence substitution, person-alias self-approval and transaction rollback.

Definer ACL/search-path tests use the real API/worker roles and attempt direct SELECT/INSERT/UPDATE/DELETE and unauthorized function calls. Paired FKs and RLS must reject cross-org/cross-pair associations, not just UI filtering. Worker tests use actual jobs, fences and outbox consumers with deterministic barriers for revoke/delete/change-evidence before publication. Actual scanner/storage failures exercise the existing dependency chain; a unit fake is never acceptance evidence.

## Required suites and evidence

Unit/components validate closed DTOs, state/interval/explanation/ranking logic and rendered accessibility. API/contract tests validate every response/error/body bound. Actual PostgreSQL covers migrations, RLS, composite references, transaction locks, append-only history and restore. Auth/security tests cover live Keycloak/session and adversarial attempts. Workers, concurrency, recovery, load and accessibility remain separate coordinated suites; browsers do not replace database tests, penetration review or biometric evaluation.

On implementation, create an explicit `synthetic_workflow` result lane with exact selector/target/fixture reconciliation. Preserve all old required inventories, source hashes, migration results, dependency audits and coverage thresholds. New feature/module coverage must expose misses rather than hide them in aggregate. Any critical security/safeguarding failure blocks progression. Manual translation/screen-reader/keyboard review and unresolved security findings are reported honestly; no manual or model test is claimed through browser success.

Record run/commit/merge-checkout, lock/runtime/fixture digests, start/end/exit, exact passed/failed/skipped/missing counts, raw restricted evidence locations and sanitized artifact checksums. Publish no private-case screenshots, full DOM, credentials, signed media paths, raw DB dumps, narrative payloads or vectors. Keep input-free foundation PNGs and minimized action/status traces; use canary/inventory checks before upload. Original failures stay preserved. Real-model accuracy, licensed-model parity, real longitudinal/ethics qualification and production erasure remain outside this phase and are never marked passed by these synthetic scenarios.
