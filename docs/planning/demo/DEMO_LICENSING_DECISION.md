Date: 2026-10-27. Scope: identify a concrete publisher-licensed demonstration package before requesting implementation approval. **No weight, image, dataset archive, generator or inference dependency was downloaded or executed.** Only public license/source text and JSON/file-reference metadata were read. [Immutable proposal](DEMO_ASSET_PROPOSAL.json) and [source lock](research/source-lock.json) record the exact identities.

## Proposed selection and decision

Recommend for owner review a **dlib v20.0 + three specifically identified dlib models + a bounded Syn-Vis-v0 image subset**. The exact code, selected weight and image publisher grants support copying, executing and displaying the selected material for a fictional demonstration under the conditions below, without a research-only or non-commercial restriction on these selected items. This is a documented publisher-license basis, not a completed real-child model qualification or a guarantee of all third-party rights. Acquisition and integration remain unauthorized until the roadmap is approved; binary integrity, input suitability and runtime compatibility are not yet tested.

The existing eight Phase 2B profiles and their execution/download blocks are unchanged. This is a new demonstration proposal in documentation, not an edit to the runtime registry or a silent clearance of InsightFace, AdaFace, SFace/YuNet, AuraFace or DeepFace packages. Research/child-evaluation and operational permissions remain separate.

## Provenance, limitations and rights boundaries

The recognition publisher discloses training from FaceScrub, VGG and scraped web images; the detector and five-point aligner also have their own published training-source descriptions. A public-domain weight grant does not establish the complete rights/authority, removals, demographic composition or overlap of those source images. We do not acquire, redistribute or retrain from those corpora. Full training-provenance/subject-authority and real longitudinal-child qualification remain unresolved. Do not describe them as legally or scientifically cleared for real missing-child operations. The scope proposed here is inference on fully fictional, publisher-licensed illustrations only; it grants no permission over training subjects, real evaluation subjects or custody decisions.

Syn-Vis-v0 is publisher-described synthetic output from Qwen-Image and Qwen-Image-Edit-2509. Their pinned model cards declare Apache-2.0; the Qwen-Image standalone license was retained. The reviewed Qwen-Image-Edit tree has a card declaration but no standalone license file listed; that limitation is recorded. **Neither generator is acquired, integrated or required at runtime.** Using the already-published CC0 images does not authorize us to recreate the publisher pipeline, run DeepFace, or adopt its caption/demographic classifiers.

Exclude `metadata.csv`, inferred race/age/gender scores, analysis cards, captions and all `misc/` images from the demonstration import. Use only individual image refs and the filename-only base/headshot mapping, with its curation license. Published predictions are not ground truth and cannot drive access, ranking, trust or a fairness claim. The source is limited and stylized; its selected images do not constitute a population-representative child cohort. Intended base/headshot linkage is fictional correspondence, not independently verified real identity. Future visual consistency review is independent of model scores; report all processing failures without cherry-picking favorable results.

Source-license grants cover only rights their licensors can grant. They are not warranties about every possible privacy, publicity, patent or upstream training claim. Preserve the explicit provenance gaps and use/distribution conditions in the approval packet. A contradictory restriction or provenance discrepancy discovered during approved acquisition stops that artifact; it does not stop unrelated synthetic application development. No publisher or institution was contacted, and no license acceptance on another party's behalf or purchase was performed.

## Frozen prospective subset

The proposal selects the first 24 base/headshot links in sorted source-filename order **before any inference**. It records the two image paths, expected LFS SHA-256 and declared size for each group. Total declared image bytes: 103,606,549. These are metadata declarations, not downloaded-byte verification. All image `bytes_verified` fields remain false.

Planned family split: 8 fictional calibration groups (6 enrolled, 2 absent) and 16 sealed demonstration groups (12 enrolled, 4 absent). Gallery uses base images for enrolled groups; the linked headshot is a probe; absent-group images never enter that gallery. Every crop/resize/augmentation of a group stays in that group's partition. This plan tests software, synthetic threshold behavior and open-set handling; tiny correlated generated pairs cannot establish independent real identification accuracy. Dates/ages are separately authored fictional scenario metadata and never inferred from the images. These are not actual aging or historical photographs.

No per-image filename/hash is exposed to public search. After phase approval, validate source hashes, scan/decode, bind clean derivative provenance and approve the actual fixture manifest before enabling demonstration inference. Unknown bytes, real uploads, third-party URLs, incompatible spaces and unlicensed additions fail closed.

## Safe integration gate after roadmap approval

1. Owner approves the exact demonstration scope, artifact/curation notices and proposed phase. This is development authorization, not institutional operating approval.
2. Acquire only immutable selected file refs in quarantine with bounded size/decompression, compare expected Git/LFS identities and sizes, compute SHA-256 for actual compressed/decompressed weights and originals, then freeze the actual runtime manifest **before parsing/loading**. Weight SHA-256 is presently unknown; do not represent a Git blob ID as a SHA-256 or claim byte verification now.
3. Build a separately pinned CPU worker image from reviewed source; lock all compiler/runtime/system/transitive dependencies and create an SBOM. Verify compatibility rather than assume the existing Python 3.13 application environment supports the native extension. No new dependency or runtime version is installed by this assessment.
4. Use no-egress, nonroot, bounded workers; no automatic download, arbitrary path, custom plugin, unsafe deserialization fallback, hidden GPU/CPU provider switch or call to an external model. Native `.dat` parsing is still an untrusted-artifact boundary; execute only after integrity review in the isolated worker.
5. Verify actual RGB/shape/dtype contract, five-point alignment and 150×150 chip/padding from the pinned [example](https://github.com/davisking/dlib/blob/2e0b3846b4dcd0953951a9c0172503c666975229/python_examples/face_recognition.py). Plan native L2 descriptor ranking, not a borrowed cosine threshold or identity probability. Existing unit-normalized synthetic vector spaces are incompatible and remain unchanged.
6. Execute all functional, real-database/RLS, security, inference/parity and three-browser tests, report failures and actual demo results, and stop for review. Download permission is not operational activation.

This assessment identifies an actionable publisher-licensed demo route with explicit conditions and remaining technical/provenance limits. It does not approve downloads, change the blocked runtime manifests, qualify a child recognizer or start implementation.
