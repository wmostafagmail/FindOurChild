# Phase 1C reporting and case management

Synthetic engineering implementation on `codex/phase-1c-reporting-case-management`, based on accepted main `9fcb6ef52057a9b46826c8ad7e03e8cb13276431`. [Phase 1B acceptance](../phase1b/ACCEPTANCE.md) records the actual PR merge and required hosted CI. Phase 2 is not authorized.

## Scope and trust boundaries

Missing/found cases remain independent reports. Child attributes, relationships, police references and photographs remain attributed claims. Contact verification establishes channel possession only. No code or image result changes case identity verification or authorizes identifying disclosure/custody/release. All production matching, lead and approval/handover operations remain disabled; the browser gateway has no such routes.

The existing Next/FastAPI/PostgreSQL design, Keycloak MFA, organization/case grants, RLS and six applied Phase 1B migrations are preserved. Forward-only migrations 0007–0021 add private reporting journals, capabilities, command ledgers, upload provenance and worker functions. All tenant/domain relations and private reporting metadata force RLS. Runtime roles remain non-owner/NOBYPASSRLS. `foc_policy` is NOLOGIN, has fixed-search-path definer functions and is never granted to a runtime principal. Public EXECUTE is revoked. `foc_worker` can execute its bounded lease/finalize/cleanup/outbox functions and cannot read application tables directly. Arbitrary SQL execution with stolen runtime credentials remains the documented trusted-server boundary; RLS is not claimed to contain a fully compromised server.

## Intake, uncertainty and reporter access

The fixed synthetic NGO intake route is privately provisioned to a dedicated moderator, without widening the accepted Phase 1B reviewer/admin accounts. The public cannot select a tenant, moderator, case grant or staff principal. The destination must be active/approved and the moderator provisioned. Otherwise intake fails safely. Unknown names/age/dates/photos are accepted; intervals, offsets, IANA timezones and closed DTOs are validated. Submitted local calendar dates retain their timezone/precision and an explicitly derived UTC interval. Names and literal text are preserved; structured uncertainty is identified separately in response projections.

Original claims and subsequent supplements/relay messages are separately encrypted immutable revisions. Staff assertions cite the source and same-case clean evidence. Verified assertions require supervisor permission and evidence; they never overwrite claims. Exact found-child custody details use separate encrypted restricted metadata, excluded from ordinary staff views, receipts, reporter views and notifications. Concern submissions enter a separate restricted safeguarding inbox; no public receipt lookup is performed. Operational investigation of that inbox and custody access remain controlled safeguarding/operator procedures, with no general-admin API override.

Browser-bound challenges, exact Origin/Fetch Metadata checks and database rate windows protect public mutations. Challenges bind an idempotency key; they are request-binding controls, not proof a human is present. Public command keys are scoped to the browser, operation and canonical body, and changed-body reuse conflicts. Contact-level and peer/session limits supplement upload quotas. There is no external anti-bot vendor.

Reporter receipts are random opaque references, never staff authorization. Access recovery always returns a neutral 202. Random verification codes are hashed, expire in ten minutes, allow at most five exchanges and are consumed under a row lock. The synthetic out-of-band delivery sink stores encrypted messages privately; no public API serves codes. External email/SMS is not configured. Reporter sessions are hashed, case-bound, expire in 30 minutes, use Secure HttpOnly Strict cookies and independent CSRF tokens, and recheck live case/org/access/revocation/claimant holds. Logout revokes server access and clears cookies. Channel verification cannot grant staff/media/custody/search authority.

Encrypted server drafts use separate hashed Secure-cookie capabilities, optimistic revisions and scoped idempotency, expire after seven days, and are removed after submission. No sensitive localStorage/IndexedDB/offline cache is used. Locale switching preserves in-memory values. The synthetic notice and contact suffix are enforced; no operational lawful basis is implied.

## Photograph and evidence intake

The private S3-compatible development adapter uses pinned SeaweedFS 4.48. Quarantine, originals and derivatives occupy separate private, versioned buckets. No storage port is published. API credentials cover bounded quarantine intake/recovery and derivative reads; originals are accessible only to the worker and controlled provisioner. Worker IAM covers required processing/version cleanup. Storage configuration hashes force reload when IAM changes. Cold-start provisioning proves an actual versioned write/read/delete after bounded readiness checks.

Each reporter-owned intent binds case/access, MIME, bytes, SHA-256, opaque key, wrapped encryption key, expiry and per-file capture metadata. The limit is five MiB/file and ten active intents/case. JPEG/PNG/WebP are supported, including image-based supporting documents. PDF/Office/SVG/remote-URL ingestion is rejected. Uploads stream through the fixed authenticated gateway and are encrypted with per-intent AES-256-GCM keys wrapped by a separate server key. Exact PUT replay returns the original bound version; changed bytes never overwrite it. Intent and completion commands are idempotent. The UI retains per-file retry progress in memory.

A least-privilege worker leases a real PostgreSQL job, reads the exact immutable version, checks bytes/checksum, runs real ClamAV INSTREAM and verifies the pinned engine reply, then decodes under Pillow format/dimension/pixel/frame limits. Unknown replies, scanner/storage/decode failures, mismatches and malware do not produce ready media. Pillow rebuilds a flat PNG from oriented RGB pixels; metadata, thumbnails, profiles and comments are not copied. Original evidence stays encrypted and private. Capture-age/date uncertainty remains encrypted provenance, not an inferred child identity. No face detector, embedding generator or production recognition model is installed.

Worker CPU/memory/PID limits and an internal-only network bound the decoder and prevent external model calls. The scanner uses the pinned image's signature snapshot without runtime Internet updates; signature freshness/operations and detection efficacy beyond controlled fixtures remain production release requirements. “Clean” is one pipeline control, not a universal malware guarantee.

## Recovery, publication and notifications

Leases carry fencing tokens and deletion generations. Finalization locks current state and rechecks organization, report access, claimant pause, deletion and generation. A stopped/unavailable verifier cannot complete publication. Retries are bounded; exhausted leases become visible dead letters. Original/derivative keys are deterministic per intent; retries verify and reuse exact encrypted immutable versions after a crash. A stale worker cannot erase versions adopted by a newer lease.

A separate cleanup sweep erases all versions/markers for an exact quarantine key, including a write lost before database bind. Unpublished orphan originals/derivatives are removed only after checking committed publication metadata. Acknowledgments occur after negative version enumeration. Ready quarantine copies and expired orphan uploads are distinct from retained case evidence. This is not a certification of whole-case erasure or backup/tombstone replay; the existing privacy-release gates remain.

Case changes, immutable journals, audit append and outbox records share a database transaction. Staff case reads require explicit live grants; org-admin membership alone gives no child access. Moderation can hold/review/reject or pause suspicious claimant contact. Active investigation requires verified contact and completed intake scanning; it does not establish identity. Closure revokes reporter access/cancels work; reopening requires a supervisor. Assignments are same-organization, purpose-bound and expiring. Notes/evidence/assertions retain source/author/revision. Journals are bounded to 200 entries; summaries expose bounded original/current claims, recent notes/assertions and ten active upload states without deleting provenance.

Outbox consumers recheck recipient grants, memberships, case deletion generation and organization status before writing a private neutral development notification. The template contains an opaque task reference and workspace link, with no child name, photo, location, contact or claim body. Delivery is deduplicated and leased; no external provider or exactly-once delivery guarantee is claimed. Serious incidents and source/custody decisions still require the approved human process.
